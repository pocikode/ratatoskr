## Notes from lead
The CA core (`internal/ca`) needs only T-004 and may be started early; the REST endpoints need T-007's router. If you start before T-007 is merged, finish the core and leave REST for the end.

## Goal
`internal/ca` generates/loads the root CA (ECDSA P-256, key encrypted at rest), issues leaf certs per SNI (SAN = host or IP, 1-year validity, cached in LRU 1024),
supports import/export/regenerate; REST serves `/ca.crt` (PEM) and `/ca.der`.

## Acceptance criteria
- [x] Leaf certs verify against the root with `x509.Verify` for DNS and IP SANs (table test incl. wildcard-looking hosts, IDNs, IPv6).
- [x] Concurrent issuance for the same host produces one cert (singleflight) — race test.
- [x] Regenerate invalidates the cache.
- [x] `tls.Config.GetCertificate` helper returns certs in < 1 ms when cached (benchmark).

## Plan (implementer, ≤15 lines)
1. `internal/ca`: `Service` over the instance.db `ca` row (cert_pem + key_pem_enc).
2. Root CA: ECDSA P-256, 10y; private key sealed with XChaCha20-Poly1305 (`internal/ca/secret.go`, key file `secret.key`, 0600) per §8.
3. Leaves: own ECDSA P-256 key per host, SAN = DNS name or IP, 365d, cached in an LRU of 1024 (`golang-lru/v2`), one cert per host via `singleflight` (`x/sync`).
4. `GetCertificate`/`TLSConfig` helpers for the proxy (ALPN `http/1.1` only, TLS 1.2 min).
5. Import/export/regenerate on the service; regenerate+import bump a generation counter and purge the cache.
6. `internal/api/rest/ca.go`: `GET /ca.crt` (PEM) and `GET /ca.der` (DER) mounted in `router.go`.
7. Tests: verify table (DNS, IP, wildcard-looking, IDN, IPv6), concurrent issuance, regenerate, import/export, cached-lookup benchmark.

## Handoff (implementer)

### What changed
- `internal/ca` (new): `Service` over the instance.db `ca` row.
  - `ca.go`: `Open(Deps)`, `Certificate(host)`, `GetCertificate`, `TLSConfig`, `CertPEM`/`CertDER`,
    `Regenerate`, `Import`, `Export`, `Generation`; LRU-1024 cache keyed by `(generation, host)` and
    `singleflight` per key, so a root replacement can never serve a leaf signed by the old root.
  - `root.go`: ECDSA P-256 root, 10 years, CN `Ratatoskr CA`; import parses PKCS#8/SEC1/PKCS#1, rejects
    a non-CA certificate, a key that does not match, and an expired CA (`ca.ErrInvalidCA`).
  - `leaf.go`: per-host ECDSA P-256 key, SAN = DNS name or IP, 365 days clamped to the root's expiry,
    host normalisation (port, `[::1]`, trailing dot, case, punycode) and validation.

    XChaCha20-Poly1305 with AAD `ratatoskr/ca/root-key/v1`.
  - `row.go`: read/write of the single `ca` row.
- `internal/api/rest/ca.go`: `GET /api/rest/ca.crt` (PEM) and `GET /api/rest/ca.der` (DER),
  `Cache-Control: no-store`, `Content-Disposition` filenames; `CAHandler` for the bare origin.
- Wiring in `internal/api/rest/router.go`, `internal/api/server.go`, `internal/app/app.go` (see above).

### How to verify
```
make check
go test -race ./internal/ca/ ./internal/api/rest/
go test -run '^$' -bench BenchmarkCertificateCached -benchtime 200000x ./internal/ca/   # 205 ns/op
go build -o /tmp/ratatoskr ./cmd/ratatoskr && /tmp/ratatoskr --data-dir /tmp/d --listen 127.0.0.1:18099
curl -D- http://127.0.0.1:18099/ca.crt           # PEM, application/x-pem-file
curl -D- http://127.0.0.1:18099/ca.der           # DER, application/pkix-cert
curl -D- http://127.0.0.1:18099/api/rest/ca.crt  # same, behind the API auth middleware
```
`openssl x509 -in ca.crt -noout -subject` → `O=Ratatoskr, CN=Ratatoskr CA`, ~10 years.

### Limitations / follow-ups
- Settings → Certificate needs the GraphQL mutations (schema is lead-owned) before the UI can call
  `Regenerate`/`Import`/`Export`.
- `Export` returns the CA private key unencrypted (it is meant to be imported elsewhere); the API layer
  must treat the response as a secret and never log it.
- An expired stored root CA only warns at start; it is not auto-regenerated (that would silently break
  every client that trusts the old one).
- Leaf certificates carry no OCSP/CRL distribution points and no `subjectAltName` beyond the SNI host;
  fine for interception, note it if a client demands more.
- `secret.go` should move to a shared secrets package when the second consumer lands (see above).
